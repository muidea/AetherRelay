# thought-flow 客户端待收口方案（2026-10-24）

本次仅修改 AetherRelay；thought-flow 仓库只读核对，不包含客户端实现、提交或部署。

## 现场依据及现有实现

x800 的 AetherRelay `33b9879` 部署后，`thought-flow` 有 12 次 `response_format` 本地拒绝，11 次之后紧接成功请求；另一次文本调用在 bootstrap 收到 403。代理增加的生成前有限恢复不能解决客户端参数配置，也不能保证外部网页端点始终可用。

只读核对同级 thought-flow 的 `internal/pkg/ai/refiner.go`、`provider_errors.go`、`json_capability.go` 与相关测试后，已见本地工作区包含：普通文本不发送 response_format、显式允许 JSON 降级、精确识别格式拒绝、按 endpoint / credential 摘要 / model 共享能力结果、首探测单飞及降级结果校验。这些工作区内容不能作为线上已部署证据；后续应先核对客户端构建版本及实际配置，不重复实现已有能力。

## P0：统一生成请求重试预算

涉及 `internal/pkg/ai/refiner.go` 的 SDK client 构造及 `chatCompletionJSON`。

- 目前聊天 SDK client 设置 `WithMaxRetries(2)`，降级请求单独设置 0；需与业务重试、代理端两次执行预算一起核对，避免 SDK / 业务 / 代理叠加重试。
- 对生成请求，默认关闭 SDK 的通用自动重试，由业务明确裁决哪些失败能重发。不能把已发送后断线、读取超时或笼统 502 当成“上游未执行”。Embeddings 等其他操作独立决策，不连带改变。
- 只有明确的格式能力拒绝，且业务显式允许降级时，允许一次去掉格式参数后的新请求；未知 400、混合拒绝能力、401、429、5xx、取消均不能触发该参数降级。
- 整个业务操作共用一个 context 截止时间，能力等待、格式探测、降级及后续解析均不得重置预算；取消立即结束等待。输入/输出估算不能当作是否已执行的证据。

验收：格式拒绝一次降级；降级失败不再嵌套重试；发送后结果未知不自动再生成；取消/超时不续期；首次成功仅调用一次；既有重试错误分类保持可操作。

## P0：确认配置与部署，消除每轮参数拒绝

涉及 `internal/pkg/ai/json_capability.go`、Provider 构造及业务配置。

- 保留现有按端点、凭据摘要、模型共享与单飞机制；核对各模块是否复用同一能力状态，避免模块各自反复探测。
- 普通文本继续不发 response_format；严格 JSON 要求继续明确拒绝或配置支持该能力的 Provider，不能通过忽略参数伪装兼容。
- 可选增加 `json_output_mode = required | preferred | off`：required 要求真实格式能力；preferred 保留显式协商降级；off 仅用于已知不支持且业务允许本地校验的入口。兼容已有 allow_json_fallback 配置，明确新旧配置优先级或拒绝冲突。
- 同名模型可能经过不同 Provider。若网关路由会变化，应优先使用稳定的显式业务路由/配置；不能凭一次拒绝永久断言模型在所有 Provider 都不支持。
- 先完成客户端已有改动的验证和版本发布，再在线核对首轮/后续轮是否仍重复出现格式拒绝，不把本地未提交实现视为线上已修复。

验收：同作用域首探测最多一次、并发不重复；不同端点/凭据/模型隔离；严格模式不会被其他模块的降级结果改变；配置变更后重新判断。

## P1：能力缓存有界与恢复

当前进程级 sync.Map 的 unsupported 状态在进程重启前不会主动恢复。建议补充有界容量、有效期以及配置/路由修订维度；例如可配置 15 分钟 TTL，过期后只允许一条业务请求重新协商，不额外发送独立生成探针。负缓存不能永久掩盖上游能力恢复，凭据明文不能进入缓存键日志。错误或取消的探测必须释放单飞等待者。

验收：过期单飞、支持恢复、配置变化、取消唤醒、容量淘汰及并发读写竞态。

## P1：保持业务 JSON 契约与可关联诊断

- 保留已有降级后 JSON 校验；继续核对业务字段类型、必填项、枚举/允许的 section key，而非只检查是否能解析成 JSON。
- 无效或截断结果不能作为成功文档入库，不能绕过现有业务校验与错误终态。对恢复失败保留可重试性及原始分类，避免无意义循环。
- ProviderError / 业务调用日志保留客户端任务 ID、HTTP 状态、稳定错误代码、failure_class、feature / unsupported_features 和响应 X-Request-Id，以便回查 AetherRelay；认证字段不参与普通诊断日志。
- `retryable` 表示是否允许策略层考虑后续尝试，不能自动等同于“可立即原样重放生成请求”。

验收：无效 JSON、合法 JSON 但字段不合法、输出截断、用户取消均不会生成成功文档；请求 ID 能对应代理归档；错误提示能区分参数、鉴权、限流和上游访问拒绝。

## 发布核对

使用客户端 Mock HTTP 回归验证参数、调用次数、并发单飞和总预算，再按 thought-flow 自身规范执行相关 Go 测试与检查。线上用同一 API Key 对普通文本、允许降级的 JSON 和严格 JSON 各核对一轮，并查看后续调用是否仍重复先 400 再成功。使用受控的小请求验证，客户端修复与代理部署分别记录版本；不以一次成功推断全部账号/出口已恢复。
