# Codex 账号模型黑名单

维护合同：`17.4.0 / CP-SCHED-013`。本功能限制指定账号槽位使用的请求模型，按完整模型 ID 精确匹配，大小写敏感。它不修改上游能力快照，也不根据上游最终响应的模型替换观测推断请求权限。

## 管理与 API

统一账号页与 Codex 账号页均提供“模型黑名单”：勾选已发现模型，或在文本框内每行输入一个完整模型 ID；编辑只修改草稿，点击“保存设置”才提交，取消不发请求。指定同邮箱下的账号时须核对槽位 ID。

```http
PATCH /admin/api/codex/accounts/<slot-id>
Content-Type: application/json

{"blocked_models":["gpt-6.1-sol"]}
```

使用管理页面现有会话认证。字段缺失表示保持原设置，`[]` 清空，`null` 和非法项返回 400。最多 256 项，每项 trim 后为 1–256 字节且不含控制字符，去重排序；允许预设尚未发现的模型。现有账号缺失字段时默认无禁用项，无额外配置或数据库迁移。

管理列表返回 `blocked_models`，已发现的被禁模型在 `model_availability` 中显示 `available=false, reason=model_blocked`。保存后从本地快照重新发布模型目录，不访问上游模型枚举；如果管理请求无法通知目录刷新，响应的 `catalog_refresh_error` 提示目录刷新待完成，账号准入策略已生效，周期任务仍会重新发布目录。

## 执行边界

首次请求、粘性会话、失败切号、compact 与 WebSocket 建连的选号共用 owner 锁内准入。保存前已准入的当前 attempt 可以完成；后续选号、Token 刷新后的重发以及现有 WebSocket 每轮发送都使用新策略。刷新重发被禁止时，无账号状态依赖的请求可以选择其它合规账号；携带 `previous_response_id` 或显式 Turn-State 的请求直接返回策略拒绝；状态相关的旧 WebSocket 返回 `model_not_found` 错误并关闭，客户端须重新建立连接，代理不迁移原账号状态。

所有支持该模型的账号均被禁用时，准入返回 `model_not_found`（HTTP 404、`retryable=false`、`failure_class=model_blocked`、无 Retry-After）。目录已经更新且不存在其它来源时，请求直接走现有模型未找到响应。其它允许账号只是满载/冷却时，沿用对应可恢复错误；被禁止账号不计入可恢复候选，不提供其冷却时间。策略拒绝不记录账号失败、额度或冷却，也不新增、延长或清除 Provider 熔断。

目录按“发现能力减去账号黑名单”聚合，最后一个允许该模型的 Codex 槽位被禁止时移除 Codex 来源；其它 Provider 的同名来源继续存在。取消黑名单可从现有有效能力快照立即恢复来源。临时满载和冷却不改变目录成员资格。

Token 刷新、同槽位重新授权和重启保留策略；v2 账号池 bundle 导出包含数组，旧文件缺失字段保留已有配置，显式空数组清除。重新授权不会以 OAuth 输入覆盖本地策略。

## 本地验证与 live 验收

本地回归覆盖统一准入的三种 transport、粘性换号、全禁用诊断、未来模型、大小写敏感、快照保真、重启与导入/重授权保持、无效批次无部分写入、刷新重发切号/拒绝、WS 下一轮及策略检查失败时停止发送、HTTP 三个入口的 404 和 Provider 健康隔离、目录重新发布与其它来源保留，以及管理页草稿/取消/清空。

2026-10-16 本地验证通过：`go test ./...`、`make check-codex`（相关 Go 竞态测试、34 项 Node 管理页测试、`go vet ./...`、diff 与凭据扫描）。原始检查输出保存在本机 `/tmp/aetherrelay-model-policy-all.log` 与 `/tmp/aetherrelay-model-policy-check-codex.log`，线上效果仍需以下 live 验收。

部署后的 live 验收步骤：

1. 记录部署 revision、目标槽位 ID、原有黑名单及当前在途请求，选一个测试模型；不能只按邮箱推断目标账号。
2. 保留另一个支持该模型且允许使用的账号。目标槽位保存黑名单后，确认管理列表的 `model_blocked`，上游能力快照仍包含该模型；分别发起普通与流式请求，通过请求归档/用量明细确认实际执行槽位为另一个允许账号。原粘性会话也须满足。
3. 对已有 WebSocket，在上一轮完成后再保存禁用策略；下一轮应返回模型不可用并关闭连接，禁止出现该轮的上游发送。重新建连可按现有准入选择其它账号。保存前已准入的轮次可能正常完成。
4. 在独立测试条件下禁止全部 Codex 槽位使用该模型，确认 Codex 来源消失；其它 Provider 存在同名来源时仍可路由，没有任何来源时返回模型未找到。不要为了这一步修改生产客户端依赖的全部账号。
5. 确认策略拒绝没有新增账号失败/冷却、Provider failure 或 circuit-open；恢复原数组后，确认有效快照可恢复该模型的调度和目录。
6. 导出 bundle，核对 `blocked_models` 包括空数组；验证重启、同槽位重授权后策略保持。刷新重发窗口及策略检查异常由本地故障注入回归覆盖，live 未触发时应明确记为未观察，不能宣称线上验证完成。

本次代码修改不自动修改 x800 账号策略，不执行生产推理、重新授权、重启或部署。
